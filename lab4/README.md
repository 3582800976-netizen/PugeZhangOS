## 这一阶段要达到什么

现在的 `pgos>` 在内核的 S 模式运行。用户进程应当拥有自己的程序、栈、寄存器状态和受限制的内存访问权限，并真正进入 U 模式执行。

先实现一个进程：创建 PCB 和用户地址空间，准备用户代码、数据、一页用户栈、trapframe 及独立的内核栈，让它真正进入 U 模式执行。计算结果和陷入记录应证明用户代码确实运行过，而不是内核打印一行“用户进程启动了”。

Lab 4 已经需要最小系统调用往返：用户传递参数并发出调用，内核保存现场、处理请求，再恢复用户执行。具体调用集合以课程提供的规格为准；Lab 5 再扩展系统调用与用户虚拟内存，不能把 Lab 4 的调用入口全部推迟。

用户代码不能直接调用内核的 `console_printf()`，也不能直接写 UART 寄存器。若需要输出，应通过已经定义的系统调用请求内核完成。

| 候选文件 | 负责什么 |
|---|---|

| `trap/user_entry.S` | 用户陷入时切换到内核栈，保存寄存器；返回时执行 `sret` |
| `trap/user_trap.c` | 区分用户系统调用、用户异常、用户期间的中断和内核自身异常 |
| `syscall/`、用户调用封装 | 接入本阶段规格规定的最小请求、参数传递和返回规则；文件名待规格确认 |

## 哪些前阶段接口需要扩展

物理页仍由 `page_alloc()` 分配，进程销毁时需要成对归还。用户代码、用户栈、内核栈和页表页的归属必须明确，创建失败也要清理已经取得的页。

当前 VM 操作围绕内核页表。需要补充“针对指定用户地址空间创建、查询、映射和销毁”的能力。用户页要设置 U 权限；内核内存和设备不能顺手标成用户可访问。

第 5 页示例使用 `VA_MAX = 1ul << 38`，低地址保留空页，代码与数据从 `USER_BASE` 开始，顶部安排内核栈、用户栈、trapframe、trampoline。需要结合实际规格确认地址、页数与权限，不直接复制示例中的固定位置；trampoline 在切换页表期间必须仍能执行，相关映射需要在用户页表和内核页表中保持约定。

当前异常入口处理 S 模式中的异常。用户入口需要从安全的内核栈开始保存现场，不能直接信任用户 `sp`。返回前填写 trapframe 中的内核栈、内核页表、处理入口等信息，设置 `stvec` 和用户 `sepc`、用户栈及 SPP 状态，再恢复现场并执行 `sret`。

`context` 与 trapframe 分工不同：前者保存内核上下文中的 `ra`、`sp`、`s0` 等状态，供 `swtch` 切换到进程的首次启动路径；后者保存用户陷入和返回所需现场。`swtch` 不直接完成权限切换，最终进入 U 模式的是 `sret`。本阶段先建立首个进程路径，完整多进程调度仍留给 Lab 6。

Lab 3 的时钟和串口中断在用户执行期间仍应正常处理。原来的内核诊断台可以留作测试入口，但它不是新用户进程。

## 本人先写什么：Spec Coding

课件第 8 页将规格分成三类：

| 规格类别 | 描述内容 | 本人需要做什么 |
|---|---|---|
| `design.yaml` | 系统目标、平台、机制、全局约束和暂不实现的能力 | 阅读并理解当前设计 |

每个函数契约需要写清 `pre`（调用前条件）、`effects`（函数做什么）、`post`（调用后状态）。这是本阶段课程明确要求本人完成的设计工作，不是要求本人重写所有 C 和汇编源码。

具体需要填写哪些模块文件和函数，应在取得课程提供的规格后逐项确认；目前不凭空创建或认定模块 YAML 文件名。个人操作与理解仍由本人记录到 `docs/NOTES.md`，有真实内容时再创建。

课件第 9 页要求两次真实提交：完成规格设计后先 commit 一次，再让 AI 按规格生成代码并 commit 一次。下载课件或更新本页的提交不能代替“规格完成”的提交，不能事后补造这一过程。

## 规格确认后的建议实现顺序

1. 保留 Lab 3 检查，建立进程记录和独立的内核栈。
2. 准备小用户程序，给代码、数据、一页用户栈和 trapframe 分配存储，建立权限及 trampoline 映射。
3. 准备最小内核上下文和首次启动路径，实现 U → S 保存与 S → U 返回。
4. 接入规格要求的最小系统调用，验证参数、处理结果及返回后继续执行。
5. 用真实计算、调用和保护异常证明用户执行，再检查错误路径、资源回收与设备中断。

这一步只要求建立最小进程执行基础，不提前实现完整调度、文件系统或 Shell。

## 实现后怎样观察和验收

| 观察项目 | 应该看到的结果 |
|---|---|
| 用户执行证据 | 用户入口 PC 正确；陷入记录表明先前模式为 U；计算结果符合预期 |
| 最小系统调用 | 用户请求到达内核；参数及结果符合规格；返回后继续执行 |
| 两种栈 | 用户栈和内核栈地址不同；陷入后在内核栈处理 |
| 隔离检查 | 用户访问内核地址、UART 或受保护代码时被拒绝 |
| 中断兼容 | 用户计算期间仍有时钟计数，串口处理正常 |
| 创建失败 | 页不足或加载失败时没有部分进程遗留，也没有页计数泄漏 |
| 回归检查 | 原有启动、物理页、页表和中断检查继续通过 |

可以增加“进程启动卡片”：展示 PID、用户入口、用户栈、内核栈与页表根。这是对真实状态的可视化，不作为用户程序已经运行的替代证据。
