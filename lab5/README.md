## 先用简单的话理解

Lab 4 已经能让一个用户程序运行、请求内核服务，再安全回到用户态。Lab 5 要让这个程序在运行过程中申请和归还堆内存。

可以把堆看成一本按页使用的本子：申请时找出够用的空白页，释放时把这些页记回空白清单，相邻的空白区合成一段。这样，中间腾出的空间也能再次使用，而不只是一直往后增加“堆顶”。

这里有三种不同的资源：记录空闲范围的链表节点、用户页表中的映射、实际存数据的物理页。归还一个链表节点，不等于已经释放了数据页。

课件中的 `malloc/free`、`new/delete`、`brk/mmap/munmap` 是层次示意，`write(1, "hi", 2)` 是流程示例。课件未明确要求完整实现这些接口，也没有规定全部调用编号、参数或错误码；这些需要在项目规格中确定。

第 6 页关于保存“下一条指令地址”的文字需要结合硬件规范阅读：RISC-V 的 `ecall` 将自身的指令地址保存到接收异常的 `epc`，内核在处理该系统调用时推进返回 PC，不能对所有异常统一加 4。依据：[RISC-V ECALL 规则](https://docs.riscv.org/reference/isa/v20260120/priv/machine.html)。

## 哪些前阶段接口需要扩展

用户陷入和系统调用分发已有往返流程。扩展服务时继续从已保存的用户寄存器读取参数，把结果写回返回寄存器。

用户 VM 需要支持指定进程的地址空间。建立页时区分读、写、执行权限；回收时归还页表和数据页，刷新必要的地址翻译缓存。

需要统一的用户内存复制入口。检查地址加长度的整数溢出、跨页范围、未映射页和只读目标；避免“检查第一字节后直接复制整段”的漏洞。

进程记录需要接入堆空闲区表头。节点仓库或物理页耗尽、映射失败时，申请应保持原状态，并归还本次取得的资源。释放时需要拒绝越界、重复释放及不属于本进程堆的范围。这些是本项目拟定的正确性要求。

串口驱动继续只负责设备；它不负责验证用户指针。验证和复制发生在内核系统调用与用户内存层。

## 建议的实现顺序

1. 确定堆范围、节点结构、分配/释放接口和错误规则，先写规格契约。
2. 从 Lab 4 建立独立阶段快照，接入共享节点仓库与进程空闲区链表。
3. 完成区间分配、分割、释放和合并，再接入用户页映射与回收。
4. 扩展系统调用和用户封装，让真正的 U 模式程序申请、写入、读取并释放堆内存。
5. 验证空间复用与失败回滚，并保持 Lab 4 的保护、中断和回收检查。

“返回错误”应当是可预测结果；未知调用和错误地址不应让整个内核 panic。

## 实现后怎样观察和验收

| 观察项目 | 应该看到的结果 |
|---|---|
| 调用往返 | 用户发出的调用编号、参数和返回结果符合 ABI |
| 用户输出 | 用户程序通过系统调用输出；没有直接访问 UART |
| 未知编号 | 返回明确错误，用户程序能够继续执行 |
| 跨页字符串 | 合法跨页输入正常；尾页未映射时安全失败 |
| 错误地址 | 内核地址、非规范地址、溢出范围和权限不符均被拒绝 |
| 堆区分配 | 前段、中间、整段分配后，空闲区记录准确 |
| 堆区释放 | 孤立区插入、相邻区扩展、两侧合并均正确；释放的空间可再次使用 |
| 资源耗尽 | 节点或物理页不足时，旧映射、空闲区和资源计数保持一致 |
| 完整回收 | 进程退出后，堆物理页、页表资源与元数据节点都归还 |
| 回归检查 | 用户陷入、隔离、时钟与串口仍正常 |
