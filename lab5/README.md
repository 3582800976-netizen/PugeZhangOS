## 先用简单的话理解

Lab 4 已经能让一个用户程序运行、请求内核服务，再安全回到用户态。Lab 5 要让这个程序在运行过程中申请和归还堆内存。

可以把堆看成一本按页使用的本子：申请时找出够用的空白页，释放时把这些页记回空白清单，相邻的空白区合成一段。这样，中间腾出的空间也能再次使用，而不只是一直往后增加“堆顶”。

这里要管好三种不同的资源：记录空闲范围的链表节点、用户页表中的映射、实际存数据的物理页。释放内存时先解除映射并归还数据页，再更新空闲区；归还链表节点本身不会释放数据页。

这次选择按页分配。用户程序传“页数”，内核返回页对齐的用户虚拟地址。它不等同于 `malloc(字节数)`；这是内核机制，可供以后实现 `malloc/free`。

课件中的 `malloc/free`、`new/delete`、`brk/mmap/munmap` 是层次示意，`write(1, "hi", 2)` 是流程示例。它没有规定所有系统调用编号、参数和错误码；本项目将它们作为自己的接口约定记录在规格中。

第 6 页关于保存“下一条指令地址”的文字需要结合硬件规范阅读：RISC-V 的 `ecall` 将自身的指令地址保存到接收异常的 `epc`，内核在处理该系统调用时推进返回 PC，不能对所有异常统一加 4。依据：[RISC-V ECALL 规则](https://docs.riscv.org/reference/isa/v20260120/priv/machine.html)。

## 模块怎样配合

按一次申请请求来读：

```text
U 模式程序
    │ 传入页数和可选地址，执行 ecall
    ▼
syscall/dispatch.c → syscall/memory.c
                         │
                         ▼
                    mm/user_heap.c ──选择并更新空闲区链表
                         │
                         ▼
                    mm/user_vm.c ──分配物理页并建立 U/R/W 映射
```

释放时沿相反方向回收映射与物理页，再将范围插回链表并合并相邻空闲区。trap 负责保存用户现场和返回用户态；它不负责管理堆。

| 候选文件 | 负责什么 |
|---|---|
| `mm/user_heap.c` | 持有共享元数据节点仓库；在每个进程的有序空闲区链表中分配、插入、分割与合并 |
| `proc/process.c` | 初始化单进程堆表头，进程退出时归还剩余元数据 |
| `mm/user_vm.c` | 验证整段映射或释放请求；清零数据页、建立权限映射、释放物理页并回收空页表 |
| `syscall/dispatch.c`、`syscall/memory.c` | 读取寄存器参数，将请求分发给堆或 VM，并返回用户地址或错误码 |
| `user/usys.S`、`include/user_api.h` | 将用户 C 函数调用转换成寄存器传参和 `ecall` |
| `monitor/`、`tests/user_heap.c` | 提供 `heap`/`htest` 入口和生产路径上的堆验证 |

保留原有模块分工；系统调用层调用进程和内存层，不把所有服务堆到 `trap/user_trap.c` 里。

## 本项目采用的堆接口

每个新进程从完整堆范围的一个空闲区开始：`0x3000` 到 `0x403000`，共 1024 个 4096 字节页。`mmap_region_t` 记录空闲区起点、页数和下一节点；内核用 32 个共享节点保存这些记录，进程 PCB 只保存链表头。

- `user_alloc_pages(pages, hint)`：`hint=0` 时从低地址开始首次适配；指定地址时必须页对齐且整段都空闲，不会静默挪到别处。成功返回虚拟地址；无空间返回 `-12`，无效参数返回 `-22`。
- `user_free_pages(address, pages)`：只接受本进程堆内完整、已分配的页；重复释放、部分重叠和越界范围会被拒绝。
- `user_heap_info(out)`：安全地把一份统计复制到用户内存。内核会先检查整个目标范围，因此跨页错误不会只改写前半部分。
- `user_heap_dump(tag)`：在内核诊断台打印真实空闲区和页数，帮助观察分割与合并。

堆页拥有用户读写权限，没有执行权限。新分配页会清零。映射、分配或元数据节点不足时，失败请求不应部分消耗物理页、页表或链表空间。

在本项目 ABI 中，堆调用编号为 6–9；Lab 4 原有调用保持不变。编号与参数均为本项目设计，并非课件规定。

“返回错误”应当是可预测结果；未知调用和错误地址不应让整个内核 panic。

## 运行与观察

从仓库根目录运行：

```bash
make -C lab5 qemu CPUS=3
```

在 `pgos>` 诊断台输入：

```text
heap
htest
user 9
user 10
user 11
quit
```

`heap` 让 U 模式程序亲自申请、读写和释放堆页，并打印 7 张真实空闲区地图；例如释放中间区域后，地图出现两个空闲段，再次申请会复用其中一段，最后相邻段合并回一个完整范围。`htest` 检查分割、整段/边界分配、合并、节点耗尽、映射失败回滚和退出回收。`user 9`、`user 10`、`user 11` 分别触发释放页读取、写入和执行故障；预期故障只结束用户进程，内核诊断台仍可继续使用。

| 观察项目 | 应该看到的结果 |
|---|---|
| 调用往返 | 通过寄存器传页数和地址，U→S→U 返回结果正确 |
| 空闲区操作 | 前端分配、中间分割、整段分配、首次适配、合并和空间复用正确 |
| 用户内存 | 新页清零、用户可读写、不可执行；跨页信息复制先完整检查 |
| 错误处理 | 无效/溢出/重复释放、安全复制错误、页或节点耗尽都不留半次变更 |
| 隔离 | 释放后读 cause 13、写 cause 15、执行 cause 12；内核继续运行 |
| 资源回收 | 用户进程退出后，页、页表和空闲区元数据恢复 |
| 回归检查 | Lab 4 用户程序、中断、权限隔离和诊断台保持可用 |
