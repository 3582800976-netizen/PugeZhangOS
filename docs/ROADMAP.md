## 2. 分成三个建设阶段

```mermaid
flowchart LR
    A["基础设施 · Lab 1–3<br/>启动 → 内存 → 中断"] --> B["进程系统 · Lab 4–6<br/>用户执行 → 系统调用 → 调度"]
    B --> C["文件系统 · Lab 7–9<br/>磁盘 → 路径 → 文件接口与 Shell"]
```

Lab 3 到 Lab 4 是一次明显变化：原来所有 C 代码在内核权限下执行，接下来要让用户程序在受限制的权限下运行，并建立正确的回内核路径。

Lab 6 到 Lab 7 的衔接是等待 I/O：磁盘操作不能一直占用 CPU，进程模块提供的睡眠和唤醒会在这里发挥作用。

Lab 8 到 Lab 9 的衔接是用户接口：内核能按路径找到文件之后，用户程序才能通过文件描述符使用它，Shell 才能加载和运行文件中的程序。

## 3. 下一步 Lab 4 如何使用现有框架

1. 以 Lab 3 的完整版本作为基础，保留已有 UART、中断、内存和诊断模块。
2. 为一个进程建立自己的状态、用户内存和内核栈；现有页分配器提供物理页。
3. 增加用户页表与权限，避免把内核 MMIO 和内核页池直接开放给用户。
4. 扩展 trap，区分“来自用户”和“来自内核”的现场及返回方式。
5. 加载一个很小的用户程序，准备寄存器后返回 U 模式。
6. 用实际用户执行、保护异常和时钟返回的观察证明完成；不要把内核 C 函数调用当作用户进程。

这一阶段不需要先实现完整磁盘和 Shell；最小用户程序可以先由构建系统嵌入，具体格式按课程要求确认。
