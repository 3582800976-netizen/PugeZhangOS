## 2. 为什么保留两条启动路径

课程 Lab 1 使用 `-bios none`，让自己的代码从 M-mode 完成降权；Lab 2 和 Lab 3 的课件采用 OpenSBI，由固件管理 M-mode 和底层定时器。把这两种方式混用，会出现地址、CSR 和中断权限错误。

### Lab 1：自己的代码完成 M → S

```text
QEMU 的复位入口
  → 0x80000000：_boot，M-mode
  → 给当前核设置独立 sp
  → boot_start：设置 PMP、异常委派和目标状态
  → mret：进入 S-mode 的 kernel_main
  → 初始化串口，输出，进入诊断台
```

`mstatus.MPP` 决定 `mret` 后的特权级，`mepc` 决定执行地址。普通函数调用只转移执行位置，不负责特权切换。初期 `satp=0`，使用裸地址访问；还没有 Sv39 翻译。

### Lab 2–3：OpenSBI 完成 M → S

```text
QEMU → 0x80000000 区域的 OpenSBI（M-mode）
  → 0x80200000：_boot，S-mode
  → 设置独立栈
  → kernel_main
  → 创建内核页表，每个核写入自己的 satp
  → Lab 3 再开启陷阱入口、PLIC 和 SBI 定时器
```

这条路径进入我们的入口时已经处于 S-mode，不能再读写 M-mode CSR。OpenSBI 使用的区域不交给页分配器，也不映射到内核页表。CLINT 的定时器管理由固件处理，我们通过 SBI 请求新的定时事件。

**修改固件方式必须同时修改加载地址和启动代码。**不能仅把 `-bios none` 换成 `-bios default`。

## 3. 从 C 源码到终端字符

```text
.c / .S
   → 编译器：各自生成 .o
   → 链接器：按链接脚本安排区域和入口
   → ELF 内核文件
   → QEMU：加载到模拟内存，CPU 开始执行
   → 内核 printf：拆解格式和变量
   → uart_putc：等待可发送，再写设备寄存器
   → QEMU：把模拟串口字符送到宿主终端
```

这里的编译器生成 RISC-V 机器指令。QEMU 模拟的是另一台机器；它不会把宿主 Linux 的 `printf`、Shell 或文件系统自动送给我们的内核。

串口在 `0x10000000`。MMIO 的意思是：对指定地址的读写由设备处理。`volatile` 保留所需的实际设备读写；它不是跨核锁。控制台的锁覆盖一整次格式化输出，而不是一个字符，因此多核消息不会互相穿插。

格式化要处理 `0`、负数、最小负整数、十六进制、地址、字符、字符串和百分号等输入。最小负整数不能直接在同一有符号类型中取反。末尾单独的 `%` 和未知格式也要有确定行为，不能读出字符串结尾以外。

## 4. 栈、物理页和页表不是同一件东西

| 概念 | 可以怎样理解 | 谁管理 |
| --- | --- | --- |
| 每核启动栈 | 当前执行的函数临时保存数据的工作空间 | 启动汇编与链接布局 |
| 物理页 | 把可用 RAM 按 4096 字节分成的小块 | 物理页分配器 |
| 页表 | 记录“虚拟地址对应哪个物理页、允许做什么”的目录 | 虚拟内存代码 |
| MMU | CPU 中按页表完成地址翻译的硬件 | CPU 根据 `satp` 自动工作 |

栈所在的物理空间属于内核已经占用的区域，不能被分配器再次分配。页表自己也要占物理页；因此必须先做好物理页分配，再创建页表。

### 物理页的生命周期

```text
启动：跳过固件和内核，按页边界确定可分配区域
  → 空闲页插入链表
申请：从链表移除一个页，标记为已分配
  → 调用者使用这一页
释放：检查所属池、对齐和当前状态
  → 标记空闲，再放回链表
```

同一个页不能同时发给两个申请者。释放不对齐地址、错误页池或已经释放的页，要被明确拒绝；不能让空闲链表被重复节点破坏。链表操作和状态统计必须在同一把锁保护下维护。

内核页池和用户页池分开，是为将来的用户进程预留资源。现在有“用户页池”不代表已经有用户程序。

### Sv39 怎样找到一个页

先把一个虚拟地址分成四段：

```text
VPN[2]：9 位 | VPN[1]：9 位 | VPN[0]：9 位 | 页内偏移：12 位
```

每张页表占 4096 字节，每个页表项占 8 字节，所以一张表有 512 个项目，9 位就能选择其中一个。

查找过程：

```text
satp 中的根页表地址
  → 用 VPN[2] 找下一层表
  → 用 VPN[1] 找下一层表
  → 用 VPN[0] 找到最终物理页及权限
  → 物理页地址加页内偏移
```

页表不是只有地址；读、写、执行权限也是检查的一部分。当前内核采用直接映射，常用虚拟地址等于物理地址，但 **CPU 仍然按页表检查权限**。额外的别名映射自检用于证明不同虚拟地址确实可以指向同一物理页，避免只用“相等地址还能访问”作为翻译证明。

自检还会实际尝试读取未映射的零地址和固件地址，写入只读代码及常量区域，检查是否收到预期的缺页异常。只有在预先登记的测试指令、原因与地址都匹配时，陷阱处理器才恢复到测试的下一步；普通意外异常仍输出诊断并停机。这是可控的内核诊断探针，不是完整的用户程序异常恢复策略。

| 区域 | 内核权限 | 原因 |
| --- | --- | --- |
| 内核代码 | R/X | 能取指执行，不能当作普通数据任意修改 |
| 只读数据 | R | 常量可读，不可写、不可执行 |
| 可写数据、动态 RAM | R/W | 存放变量，不执行数据 |
| UART、PLIC、QEMU 关机设备 | R/W | 驱动读写设备寄存器；模拟机器正常关机 |
| OpenSBI 固件、CLINT | 不映射 | 由 M-mode 固件管理 |

创建共享内核页表只需一个核完成；每个核都必须写自己的 `satp` 并执行 `sfence.vma`。一个核启用了分页，不代表其他核也启用了。

## 5. 中断如何打断程序再返回

普通调用是代码自己调用函数。中断是外部事件通知 CPU，需要安全地暂停当前执行。

```text
正常内核执行
  → 设备或时钟发来中断
  → CPU 保存返回位置和陷阱原因，跳到 stvec
  → 汇编保存通用寄存器
  → C 处理函数判断中断类型
  → 处理设备／重新预约时钟
  → 汇编恢复通用寄存器
  → sret 返回原来的执行流
```

CPU 自动保存的状态不足以保护所有 C 代码。中断处理函数会使用通用寄存器，因此汇编入口必须保存它们，返回前恢复。否则，一个普通算式可能被中断悄悄改变。

### UART 输入中断

```text
用户按键 → QEMU UART → PLIC → S-mode 外部中断
  → 领取中断号
  → 从 UART 读取已有字符，放入接收环形缓冲
  → 通知 PLIC 处理完成
  → 主执行流读取缓冲并编辑、执行诊断命令
```

中断处理函数做小而确定的事情，不在里面运行整个命令解析器。诊断台接收 ASCII 命令，支持回车换行、退格和删除；超长命令整行丢弃，并等待行尾，防止执行一个被截断的命令。

Lab 1 和 Lab 2 的输入暂时轮询 UART；Lab 3 的输入来自中断写入的缓冲。因此能输入文字不等于已经实现中断，要结合 PLIC 处理代码和实际中断计数一起核对。

### 时钟中断

每个核通过 SBI 预约下一次时钟事件。事件发生时，S-mode 收到定时器中断，增加本核计数，再预约下一次。必须持续重新预约，不能收到一次就不再触发。

```text
预约时间 T
  → 到达 T，产生时钟中断
  → ticks 加 1
  → 预约新的时间
  → 返回正常执行
```

`ticks` 是中断次数，不是秒数。不同核的数值可能略有不同；验收关注它们都持续增长，而不是要求完全相等。

## 6. 小巧思：让内核能够解释自己

特色集中在诊断能力，不增加桌面等与前三个实验无关的大功能。

1. **每核启动记录。**每个核记录自己真实经过的阶段、独立栈范围和实际 `satp`；完成后发布状态。输出核等待明确的完成条件，避免把“还没启动完”误判为失败。
2. **物理页统计与所有权检查。**显示两个页池的总页数、空闲页数、已分配页数和拒绝次数；检查重复释放及错误归还，并验证自检后页数恢复。
3. **可查询的地址翻译。**查看 UART、代码、数据及保护区域的映射，联系权限和实际运行；自检通过额外虚拟地址实际读写同一个物理页，证明 CPU 在执行地址翻译。诊断别名与它的页表在初始化时固定保留，不反复修改共享页表。
4. **每核心跳和输入计数。**把时钟次数、串口中断次数、接收字节数和缓冲丢弃数展示出来。计数来自实际处理路径，不打印写死的成功值。

这些功能可以用于答辩：当被问到“你怎么知道它真的实现了”，有具体观测和不变量可解释。

## 7. 如何运行和检查

在项目目录中运行：

```bash
make LAB=1 CPUS=3
make qemu LAB=1 CPUS=3

make qemu LAB=2 CPUS=3
make qemu LAB=3 CPUS=3
```

`LAB` 选择阶段，`CPUS` 选择活动核数。不同配置的产物放在独立构建目录，避免改了宏却误用旧目标文件：

```text
build/lab1-cpu3/kernel.elf
build/lab2-cpu3/kernel.elf
build/lab3-cpu3/kernel.elf
```

看到 `pgos> ` 后可以输入：

| 命令 | 做什么 |
| --- | --- |
| `help` | 查看命令及当前阶段 |
| `boot` | 查看每个核的启动记录、栈和页表状态 |
| `mem` | 查看内核／用户物理页池统计 |
| `vm` | 查看代表性区域的地址映射和权限 |
| `vm 十六进制地址` | 查询某个地址的物理地址、权限及三级页表索引 |
| `ticks` | 查看各核时钟次数；仅 Lab 3 有持续的时钟中断 |
| `irq` | 查看 UART 输入中断与接收统计 |
| `test` | 运行当前阶段已实现模块的自检 |
| `echo 内容` | 回显文字，测试输入和行编辑 |
| `quit` | 正常关闭模拟机器，退出 QEMU |

未到对应阶段的功能应说明未启用，而不是假装通过。

这次在 **QEMU 5.1.0 `virt`、128 MiB RAM、RISC-V GCC 13.3.0** 上验证。可选核数为 1–8；自动矩阵选择 1、2、3、8 核。平台的时间基准固定为 10 MHz，定时周期设为 100 Hz，因此 `ticks` 是次数而不是秒。
