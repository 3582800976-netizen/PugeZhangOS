## 这一阶段要达到什么

inode 记录文件或目录自身的信息，例如类型、大小和数据块位置。目录项把一个名字关联到 inode 编号；路径解析沿着这些名字逐层查找。

例如 `/demo/hello`：先找根目录中的 `demo`，确认它是目录，再在其中找 `hello`。文件名和文件内容不是同一个东西，路径字符串也不是磁盘地址。

先实现清楚的小文件系统：认识磁盘布局，能读取根目录、查找路径和访问 inode 数据。打开文件后的描述符与偏移由 Lab 9 管理。

## 哪些前阶段接口需要扩展

块缓存需要稳定地提供指定块，并明确块内容的锁、引用和写回规则。inode 读取与目录查找都走这个入口。

镜像工具与内核必须共享同一份布局约定：块大小、区域位置、inode 编号和数据格式。工具在宿主运行，内核在 RISC-V 运行，不能依赖宿主指针大小或结构体隐含填充。

inode 需要自己的引用与锁，避免并发修改大小或块映射时得到不一致结果。资源分配失败时要回滚本次取得的资源。

路径查找需要一个明确起点。绝对路径从根目录开始；相对路径需要进程当前目录，本阶段可先提供根目录起点，随后按课件接入当前目录。

传入路径的用户内存检查继续复用 Lab 5。文件系统内部处理的是已经安全复制到内核的路径，而不是未检查的用户指针。

## 建议的实现顺序

1. 确定并说明磁盘布局，用镜像工具创建已知内容。
2. 读取总布局并校验容量、格式和区域范围。
3. 读取 inode，确认大小、类型及数据块映射。
4. 查询根目录中的名字，再实现逐段路径查找。
5. 根据详细要求接入创建、数据增长与目录修改。
6. 检查错误路径、锁顺序和资源回收，并重新启动读取已保存内容。

成功重启读取是正常写回的验收；未经专门设计和故障注入，不宣称具备断电一致性。

## 实现后怎样观察和验收

| 观察项目 | 应该看到的结果 |
|---|---|
| 预置文件 | inode 元信息和数据内容与镜像工具生成结果一致 |
| 路径查找 | 根目录和多级目录能解析到正确 inode |
| 同名不同目录 | 不把 `/a/x` 与 `/b/x` 混成一个文件 |
| 错误路径 | 名字不存在、中间节点不是目录、名字过长等情况安全失败 |
| 引用与并发 | 反复查找、读取和释放后引用计数不泄漏 |
| 块边界 | 跨块数据正确；超容量或分配失败时没有半完成元数据 |
| 正常持久化 | 正常写回并重启后，已承诺保存的数据可重新读取 |

可以提供路径追踪，展示“当前 inode、当前名字、下一个 inode”，让 `/demo/hello` 的查找路线可见。缓存、inode 和目录项的统计分别展示，避免把它们当成同一种对象。
