## 这一阶段要达到什么

让多个进程轮流运行，保存并恢复各自的执行位置。进程暂时无法继续时可以睡眠，条件满足后被唤醒；退出后，状态和资源按课程规则回收。课程规格列出了进程状态、锁顺序和失败行为，实现时要先理解这些契约。

进程状态转换是本阶段的主线：

```text
EMBRYO -> RUNNABLE -> RUNNING -> RUNNABLE
                           |        ^
                           v        |
                       SLEEPING ----+
                           |
                           v
                         ZOMBIE -> 回收
```

这是帮助理解的简图；实际状态与转移条件以课程 `spec/modules/process.yaml` 为准。

## 建议的项目模块布局

以下是项目候选职责，不是课程仓库源码文件的承诺；课程实际目录见其 `lab6` 分支 README。

| 候选文件 | 负责什么 |
|---|---|
| `proc/process.c` | 分配进程记录、维护状态与资源归属 |
| `proc/scheduler.c` | 选择可运行进程，协调每核调度循环 |
| `proc/lifecycle.c` | 退出、等待与最终回收 |
| `proc/sleep.c` | 在条件或通道上睡眠，配对唤醒 |
| `trap/context.S` | 保存和恢复内核函数切换所需的上下文 |
| `trap/user_trap.c` | 处理用户陷入及安全的时钟抢占 |
| `syscall/process.c` | 接入 fork、退出、等待和睡眠服务 |
| `tests/scheduler.c` | 检查切换、并发所有权与资源回收 |

中断保存的是被打断程序的完整现场；内核函数间的上下文切换通常保存 ABI 要求保留的寄存器、栈和返回位置。这两种现场用途不同。

## 哪些前阶段接口需要扩展

每个核心需要“当前运行进程”的状态；同一进程不能同时被两个核心选中。时钟处理要提供让出 CPU 的时机，实际切换应发生在允许切换的位置，不能持有不相关的驱动锁就跳到其他进程。

进程切换需要切换对应页表与内核栈；返回用户态时恢复正确的现场。资源回收不能释放仍在运行的栈或仍被使用的页表。睡眠接口还需要与保护条件的锁配合，避免检查条件后、真正睡眠前丢失唤醒。

## 建议的理解与实现顺序

1. 先看懂进程状态、每核当前进程和锁的交接规则，并由你理解后填写课程函数契约。
2. 追踪 `scheduler -> swtch -> proc_sched -> scheduler` 一次完整切换，弄清楚为什么需要两次上下文切换才能从进程 A 转到 B。
3. 先做进程创建、fork 与父子内存独立，再做 exit/wait 和资源回收。
4. 做 sleep/wakeup、共享 tick 和睡眠锁；检查条件锁与睡眠锁的交接，避免丢失唤醒。
5. 接入内核态、用户态时钟抢占，最后在 1 hart 和 2 hart 下运行完整验收。

每一步都保留 Lab 5 的用户权限检查，不能为了切换方便而共享所有用户内存。

## 实现后怎样验收

课程的具体用例和预期输出见上方指导书链接。重点包括：

| 检查内容 | 预期结果 |
|---|---|
| 单核和双核调度 | 两种配置都进入用户态；同一 PID 不会同时在两个 hart 运行 |
| fork 层级 | 连续两次 fork 后，level 1/2/3 输出分别出现 1/2/4 次 |
| 地址空间复制 | 父子 heap、stack、mmap 数据互不影响 |
| exit/wait | 父进程取回子 PID 和退出码；无子进程、非法地址及资源回收边界符合规格 |
| sleep/wakeup | `sleep(30)` 至少等 30 个共享 tick；其他进程期间仍能运行，无丢失唤醒 |
| 睡眠锁 | 竞争者阻塞，释放后可继续竞争，非持有者不能释放锁 |
| 错误与失败 | 非法用户行为隔离在进程内；fork 失败时不留下半成品或泄漏资源 |

可以提供有限长度的调度事件环，记录“时间、核心、PID、原因”，由诊断命令读取。避免在每次时钟中断中大量打印，以免改变调度行为。
