## 这一阶段要达到什么

给用户进程提供打开、读取、写入和关闭文件的入口。文件描述符是进程内部的小整数，指向内核维护的打开文件对象；它不是 inode 编号，也不是用户直接持有的磁盘指针。

用户 Shell 是一个普通用户程序：读取命令，解析参数，请求创建或加载程序，并等待它结束。它应通过系统调用工作，而不是把内核诊断台改个提示符就当成 Shell。

先实现少量命令和清楚的行为。管道、重定向、复杂引号与脚本属于后续候选扩展；是否属于课程必做项待详细课件确认。

## 哪些前阶段接口需要扩展

进程需要描述符表。独立打开通常应有独立文件偏移；若要求复制或继承描述符，需要明确哪些引用与偏移共享，不能仅复制一个裸指针。

文件层调用 inode 数据接口，系统调用层负责用户复制和权限检查。锁和引用沿调用链有清楚的获得与释放规则。

`exec` 需要从文件读取程序并校验格式、段范围、整数溢出和映射权限。先构造完整新映像，成功后再替换旧映像；失败不能让进程只剩一半新页表。

用户参数需要复制到新用户栈，长度和数量有明确上限。用户入口、栈布局和 ABI 必须与用户程序构建方式一致。

进程退出需要关闭持有的文件引用并释放映像；Shell 要等待子进程并回收状态。输入输出通过用户可用的控制台接口，而非直接读写设备寄存器。

## 建议的实现顺序

1. 建立文件对象和进程描述符表，先完成基本打开与关闭。
2. 接入读写调用，检查偏移、权限和用户复制。
3. 从文件加载简单用户程序，验证参数、用户栈和失败回滚。
4. 根据既有进程 API 实现 Shell 的执行和等待路径。
5. 接入少量用户工具，明确可用命令与错误消息。
6. 多轮运行并退出，检查文件引用、进程记录和物理页回到基线。

文件 API、程序加载和 Shell 分开验收，避免一条命令失败时无法判断错误属于哪一层。

## 实现后怎样观察和验收

| 观察项目 | 应该看到的结果 |
|---|---|
| 文件读写 | 内容正确，偏移按成功读写的字节数更新 |
| 独立打开 | 同一文件的两次独立打开各自维护偏移 |
| 错误描述符 | 越界、已关闭或模式不符时返回错误，不破坏其他对象 |
| 程序加载 | 真实进入新用户入口，参数与用户栈符合约定 |
| 加载失败 | 格式错误、缺文件或内存不足时旧进程仍完整可用 |
| 用户 Shell | 能启动工具、等待结束；未知命令后继续接受下一条输入 |
| 生命周期 | 连续执行多轮后没有文件引用、进程记录或页计数泄漏 |

可以给 Shell 提供可选的执行说明：命令名 → 文件路径 → 进程编号 → 退出结果。细节仍由内核诊断台查询，正常用户提示保持简单。
